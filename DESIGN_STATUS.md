# DESIGN_STATUS.md — post-Phase-1/2 route audit

Written by D3.1. Cross-references the 20 routes from `next build`'s
route table (= STATUS.md's 19 mobile-sourced screens + the
`/invoices/preview` route, which STATUS.md's row 12 already covers)
against the foundation work done in Phase 1 (icons/logos, collapsible
sidebar, themed dialogs) and Phase 2 (design tokens, loading/empty/
error states, primitive accessibility).

**No browser/screenshot tool was available this session** (confirmed
in D0.3, repeated here per DESIGN_LOOP.md's Stop Condition
requirement) — every judgment below is from reading the actual
rendered JSX/CSS output (component structure, Tailwind classes,
computed color/spacing paths, and for the two hardest-to-eyeball
cases, directly computed WCAG contrast ratios rather than a visual
guess) against the researched standards in DESIGN_ASSUMPTIONS.md, not
from looking at pixels. **A human's first task tomorrow should be
`npm run dev` and a visual click-through of every row below**,
especially the sidebar collapse animation and the dialog/toast
positioning, which can only really be judged by eye.

Verification method used for every row: grepped the full route's
component tree for emoji/glyph-as-icon (should be zero, D1.1),
`window.alert`/`window.confirm` (should be zero, D1.3), raw hex color
one-offs (D2.1), and read the loading/empty/error handling directly
against the D2.2 shared components.

## Cross-cutting findings not tied to one route

- **D4.1** (routes `/login`, `/register`): password-visibility toggle
  is plain "Show"/"Hide" text in both `LoginForm.tsx` and
  `RegisterForm.tsx`. Not an emoji (so D1.1's sweep correctly didn't
  flag it), but inconsistent with the icon system established
  elsewhere — every other app in this space uses an eye icon here,
  and this app already uses `Eye`/`EyeOff`-family icons via
  `lucide-react` (`Eye` already imported in `PlansContent.tsx`).
- **D4.2** (route `/_not-found`): no `src/app/not-found.tsx` exists,
  so Next.js's completely unstyled default renders. Every other route
  in this app now has a consistent, tokenized, professional look —
  this is the one remaining place a user can land on raw
  browser-default HTML.
- **D4.3** (app-wide, `src/app/layout.tsx`): `metadata.title` is
  still `"Create Next App"` and `metadata.description` is still
  `"Generated by create next app"` — the scaffold's placeholder,
  never updated. Shows in the browser tab and any link-preview card
  for every route in the app.
- **D4.4** (repo-wide, not a specific route): `public/` still has
  five unused scaffold SVGs (`file.svg`, `globe.svg`, `next.svg`,
  `vercel.svg`, `window.svg`) left over from `create-next-app`,
  confirmed by grep to be referenced nowhere in `src/`. Dead weight,
  not a visual bug on any page, but cheap to clean up while already
  auditing every route.
